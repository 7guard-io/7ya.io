# 7YA.IO Agent Operating Rules

This repository controls the public `7ya.io` production site.

All coding agents, automation agents, AI operators and human operators must read this file before changing the platform.

## Canonical system

- Repository: `7guard-io/7ya.io`
- Default branch: `main`
- Production workflow: `.github/workflows/pages.yml`
- Workflow name: `Publish 7YA Production Site`
- Publishing target: GitHub Pages
- Deployment trigger: manual `workflow_dispatch`
- Live domain: `https://7ya.io`
- Release architecture: immutable full-site static artifact assembled from repository-root HTML, route folders and public assets
- Current migration state: pending reviewed merge, manual deployment and independent live verification
- Governance and evidence vault: Datasite project `7YA.IO Sovereign Control Room` when available and verified

## Source-of-truth order

1. Canonical repository state
2. Latest verified production deployment
3. Verified Datasite governance and evidence records
4. Current task instruction
5. Chat memory as non-authoritative context only

Do not rely on remembered assumptions, ZIP files, copied folders, obsolete repositories or temporary exports.

## Required reading

Before changing code, read:

- `docs/7YA_OPERATING_CONTRACT.md`
- `docs/DEPLOYMENT_RUNBOOK.md`
- `docs/LIVE_VERIFICATION_CHECKLIST.md`
- `docs/ARCHITECTURE_DECISIONS.md`
- `docs/RELEASE_STATE.json`

## Division of authority

| System | Role |
| --- | --- |
| GitHub | Code, branches, commits, pull requests and production deployment |
| GitHub Pages | Canonical production hosting target |
| `7ya.io` | Live public result |
| Datasite | Governance vault, evidence, approvals, release records and audit trail |
| ChatGPT / coding agents | Operators that inspect current state, edit through GitHub and verify results |
| Chat memory | Helpful context only; never source of truth |

Datasite is not the website editor or deployment platform. Vercel and Netlify are not canonical production targets.

## Required operating sequence

1. Verify the canonical repository and default branch.
2. Inspect `.github/workflows/pages.yml` and `docs/RELEASE_STATE.json`.
3. Inspect the live site before editing.
4. Record before-state evidence.
5. Check blockers, including issue `#83`.
6. Create a dedicated branch.
7. Make the minimum required changes.
8. Run available local validations and assemble the exact production artifact locally.
9. Review the final diff.
10. Open a pull request.
11. Merge only after validation and explicit approval.
12. Confirm the merged commit exists on `main`.
13. Run only the verified manual production workflow when safe.
14. Confirm workflow success.
15. Verify `https://7ya.io` on mobile and desktop.
16. Verify every route required by the current production architecture.
17. Archive commit, workflow, screenshots, route results and rollback point.

## Current route rule

The approved release architecture is a full static site. Critical routes are `/`, `/journey/`, `/igor-vepretski/`, `/starton/` and `/evidence/`. The workflow also packages the additional public routes listed in `docs/RELEASE_STATE.json`. A merge or successful artifact assembly does not make these routes live; publication is complete only after the manual Pages workflow succeeds and the public domain is independently verified.

## Artifact rule

The public site is not generated by `npm run build`. The production artifact is assembled into `dist/` from approved root files, route directories and assets. `scripts/inject-ga4.mjs` runs against `dist/` and must provide complete GA4 coverage without modifying source HTML.

## Stop conditions

Stop and report a conflict when:

- Repository or production workflow cannot be verified.
- Deployment target or workflow name differs from governance.
- Live state conflicts with repository state.
- Datasite governance conflicts with repository governance.
- Required validation cannot run.
- Issue `#83` or another blocker prevents safe deployment.
- Redirect or `noindex` behavior appears in the homepage artifact.
- A raw secret is requested in a normal document.

## Secrets rule

Never store raw passwords, tokens, API keys or private keys in ordinary repository or Datasite documents. Record only managed location, controller, consuming system and rotation notes.

## Required final report

Every completed task must report:

- Production status
- Repository and branch used
- Files changed
- Tests completed
- Pull request and commit
- Deployment workflow result
- Live routes verified
- Evidence archived
- Remaining blockers
- Exact rollback point
