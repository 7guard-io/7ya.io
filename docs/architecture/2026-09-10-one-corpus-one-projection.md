# 7YA — One Corpus → One Projection → Many Experiences

## Mission
7YA is not a generic personal website. It is the public, source-linked, living representation of Igor Vepretski's life, work, media, StartOn, public action, creation and research.

## Product truth
The user-facing result is the authority. A build, health check, sync status or successful API response is not success unless the live experience visibly presents authentic Igor content.

## Architecture rule
All public content sources converge into one normalized public corpus. One projection builder ranks and prepares presentation-ready objects. Homepage and deep routes consume that prepared projection; they do not independently rediscover or re-normalize the same sources.

PUBLIC SOURCES
→ INGEST
→ NORMALIZED PUBLIC CORPUS
→ PERSONAL PROJECTION SNAPSHOT
→ HOME / LIBRARY / MEDIA / STARTON / EVIDENCE / PRESS / AI

## Content coverage
The corpus may include Instagram, TikTok, YouTube, Facebook, LinkedIn, Telegram, X, Threads, press, podcasts, music, StartOn, public documents, photographs, research and other source-linked public material.

## Normalized object contract
Each object should resolve to: id, canonicalId, layer, title, summary, date/year, platform, publisher, mediaType, sourceUrl, imageUrl/thumbnail, embed strategy, topics, life chapter, relationships, evidence status and source-bound metrics when available.

## No duplicate work
- Social connectors ingest; presentation routes do not independently re-fetch the same platform feeds.
- Discovery enriches the corpus; it does not become a second presentation database.
- Visual Registry resolves media; it does not become another discovery engine.
- Agent Mesh observes changes and quality; it does not repeat ingestion already performed elsewhere.
- Homepage consumes a prepared projection; it does not run broad discovery while a visitor waits.

## Visual doctrine
REAL BEFORE GENERATED.
Use authentic Igor media before generic graphics or synthesized substitutes. One source-linked object per card; no collage. Broken media degrades to a source poster, never to an unrelated recurring hero image.

## Homepage mission
A visitor should immediately experience:
PERSON → PROOF → PURPOSE → PARTICIPATION.
The page should feel like Igor's living public story, not an internal dashboard.

## Acceptance gate
A release is not accepted until external mobile and desktop inspection of the public route visibly shows:
1. Igor as the unmistakable subject.
2. Authentic media from multiple life chapters and platforms.
3. StartOn proof.
4. Public work / media / creation / music / research represented without generic filler.
5. Source actions attached to content.
6. More than a hero-only first paint; meaningful depth must render.
7. HE / EN / RU remain coherent.
8. No horizontal overflow, clipping, repeated fallback imagery or empty content walls.

If APIs report hundreds of objects but the live experience shows only a sparse fallback, the release fails.

## Operational simplification target
Keep only the recurring jobs that materially improve the public corpus or projection. Prefer:
1. Content Sync — incremental source ingestion.
2. Projection Builder — dedupe/rank/materialize presentation-ready snapshot.
Optional observers/canaries must not sit on the visitor critical path.
