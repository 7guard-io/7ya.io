# סביבת 7YA עצמאית מספק אירוח

## החלטה

היישום הציבורי נבנה מעכשיו כארטיפקט סטטי מלא מתוך המאגר הקנוני. הוא אינו מייבא SDK של AppDeploy, אינו קורא ל־AppDeploy בזמן ריצה ואינו זקוק ל־backend של הספק כדי להציג את הבית, הסיפור, העשייה, המדיה, המקורות או דרכי הקשר.

הארטיפקט נבנה באמצעות:

```bash
npm ci
npm run release:gate
npm run build:cloudflare
```

תיקיית `dist/` היא יחידת הפרסום. אפשר לשרת אותה מ־Cloudflare Pages, GitHub Pages, שרת קבצים רגיל או כל CDN סטטי, בלי לשנות את תוכן האתר.

## מסלול הפרסום

- GitHub הוא מקור הקוד והביקורת.
- Cloudflare Pages הוא יעד הפרסום העצמאי המועדף.
- כל push ל־`main` מפעיל gate מלא, בונה את `dist/`, בודק שאין בו תלות בזמן־ריצה ב־AppDeploy ומפרסם את אותו ארטיפקט.
- החלפת DNS של `7ya.io` היא פעולה נפרדת. אין להסיק מ־PR או מבנייה מוצלחת שהדומיין כבר עבר.
- רשומות דואר, nameservers ורשומות TXT אינן משתנות במסלול הפרסום הזה.

## יציאה בטוחה מ־AppDeploy

עד שהדומיין הקנוני מציג את סמן הבנייה החדש, AppDeploy נשאר מצב הייצור המתועד האחרון ולא מוחקים אותו. סדר הפעולות הבטוח הוא:

1. לפרסם את הארטיפקט ב־`7ya-io.pages.dev`.
2. לאמת מסלולים קריטיים, כותרות, canonical, מובייל וקישורים.
3. לשמור receipt עם commit, hash של manifest וכתובת preview.
4. להעביר רק את רשומות ה־web של `7ya.io` ו־`www`; לא לגעת בדואר.
5. לוודא ב־no-cache שהדומיין מציג `igor-personal-independent-static-20260918-v2`.
6. רק אז להגדיר את AppDeploy כ־rollback היסטורי ולא כתלות פעילה.

## גבול ה־AI

הבית הציבורי והארכיון עובדים ללא backend. רכיב Ask Igor יכול להציג ניווט וחומר ציבורי מקומי גם בלי API. יכולות יצירה עתידיות חייבות להתחבר דרך ממשק ספק־נייטרלי ואסור להן להפוך לתנאי להצגת האתר.
